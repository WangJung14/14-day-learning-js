I. Destructuring : giải nén dữ liệu
1.1 Tại sao lại cần phải Destructuring ?
Trước khi đi vào bài học mới hãy nhìn lại day3, mình đã được học biến và object trong JS
Giả sử nếu xây dựng một trang web quản lý sinh viên 
const student = {
    name : "Trung",
    age : 21,
    major : "Information Technology"
};
Đối tượng Student lưu thông tin của sinh viên gồm 3 thuộc tính:
 - name : tên sinh viên
 - age : tuổi sinh viên
 - major : ngành học của sinh viên
Bây giờ nếu mình muốn lấy tên và tuổi của sinh viên đó hiển thị lên giao diện
Với những những kiến thức đã học từ bài học trước đó, mình có thể thực hiện như sau:
const name =  student.name;
const age = student.age;

console.log(name);
console.log(age);

--> output sẽ là :
An 
20
Cách này hoàn toàn đúng , không có bị lỗi gì hết. Nhưng tưởng tượng nếu đối tượng có 20 thuộc tính và mình cần phải lấy 10 thuộc tính trong số đó. Với phương pháp như trên bắt buộc mình phải viết nhiều dòng code để truy cập vào từng thuộc tính

Để giải quyết vấn đề đó JS đã cung cấp cho chúng ta 1 giải pháp giúp lấy nhiều giá trị từ cùng một nguồn dữ liệu ngắn gọn hơn
const {name , age } = student;
--> Đây chính là Object Destructuring

1.2 Bản chất của Object Destructuring
Hãy phân tích đoạn code dưới đây 
const {age , name } = student;

const = student --> một phép khai báo kết hợp giải nén dữ liệu
student ở đây là nguồn dữ liệu , đây là object chứa những thuộc tính mà chúng ta muốn lấy
name và age là tên các thuộc tính cần lấy , JS sẽ tìm thuộc tính name và age trong student sau đó sẽ gán giá trị của nó cho biến name và age.
Về mặt ý nghĩa thì đoạn code ở trên sẽ tương đương với :
const age = student.age;
const name = student.name;
!!!!Nhưng có một điểm cục kỳ quan trọng: Object Destructuring dựa vào tên thuộc tính không dựa vòa vị trí thuộc tính trong object
const student = {
  major: "IT",
  age: 20,
  name: "Trung"
};
const { name, age } = student;

Dù name nằm cuối object nhưng biến name vẫn nhận giá trị là "Trung".
Vì JS tìm thuộc titnhs bằng tên name , chứ không lấy htuoojc tính đầu tiên hay thứ 2 theo thứ tự khai báo
--> Đây là điểm khác biệt mà chúng ta cần phải nắm chắc để có thể học tiếp Array Destructuring

1.3 Array Destructuring khác gì với Destructuring Object
Chúng ta sẽ có 2 đoạn code như sau:

 1. Array Destructuring:
    const scores = [8,9,10];
    const [a,b,c] = scores;
 2. Object Destructuring:
    const student = {
        name : "Trung",
        age : 21,
        major : "IT"
    };

Với Array thì kết quả trả về sẽ là 
a // 8
b // 9
c // 10
Nếu mình thay đổi biến a b c thành xyz thì  biến x vẫn có giá trị là 8 và y có giá trị là 9 , z có giá trị là 10
Điều này cho thấy rằng , Array chỉ quan tâm đến vị trí mà không quan tâm đến tên biến là gì.

Ngược lại với Object thì 
const { age, name } = student;
const { name , age } = student;
Biến age vẫn sẽ trả về là 21 và biến name vẫn sẽ trả về là "Trung" mặc kệ cho việc có thay đổi vị trí trong dấu ngoặc
!!! Chúng ta có thể dựa vào [] và {} để nhận biết cách JS giải nén cho từng loại dữ liệu.

1.4 Vì sao React dùng Destructuring rất nhiều ?
Trong React một component có thể nhận dữ liệu từ component cha thông qua props
Ví dụ: nếu chúng ta có component hiển thị thẻ sinh viên :
function studentIdCard(props){
    return(
        <div>
            <h2>{props.name}</h2>
            <p>{props.age}</p>
        </div>
    );
}

khi sử dụng 
<studentIdCard name "Trung" age={20} />

React sẽ truyền các props vào component dưới dạng 1 object có các thuộc tính tương ứng.
Vậy trong component mỗi lần muốn lấy tên thì mình phải viết props.name; muốn lấy tuổi thì viết props.age.
Với destructuring thì ta có thể viết:
function StudentCard({ name, age }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>{age}</p>
    </div>
  );
}
Hai cách đều có thể cho ra giao diện tương ứng với nhau
Nhưng cách thứ 2 sẽ giúp chúng ta thấy ngay component đang sử dụng những dữ liệu nào.

Vậy còn useState ?
Thông thường thì mình có thể thấy cú pháp sau:
const [ count , setCount ] = useState(0);
Nếu đã hiểu được bản chất của Array Destructuring ở trên thì dòng code này sẽ không còn khó hiểu nữa
Hàm useState(0) trả về một mảng gồm 2 phần tử : giá trị của state hiện tại và hàm dùng để cập nhật state
Ta có thể tưởng tượng kết quả như sau:
[0,someSetterFunction]
Vì vậy :
 - count nhận phần tử ở vị trí thứ nhất , tức là giá trị state
 - setCount nhận phần tử ở vị trí thứ 2 , tức là hàm cập nhật state

Take note !!!:

Ở phần học này cần nhớ 3 quy tăc:
 1. Object Destructuring dựa vào tên thuộc tính không dựa vào thứ tự khai báo. ex : const { name , age } = student;
 2. Array Destructuring dựa vào giá trị phần tử trong mảng. ex: const [ first , second ] = number;
 3. Renaming : cú pháp propertyName : variableName cho phép lấy thuộc itnhs bằng tên cũ và lưu giá trị vào biến có tên mới. Ex : const { name : fullName } = student;

1.5 Default Values: Giá trị mặc định 
Đây là một phần rất quan trọng, đặc biệt khi em làm việc với dữ liệu từ API hoặc nhận props trong React.

Chúng ta sẽ có tình huống thực tế nhưu sau :
Giả sử mình đang xây 1 trang thể hiện thông tin của cuốn sách:
const book = {
    title : "How to learn Javascript in 14 day",
    price : 10,
};
console.log(book.author);
--> kết quả sẽ hiện ra là undefined
??? tại sao 
Để giải thích cho vấn đề trên: Bởi vì object book không có thuộc tính author. JS không tự tạo ra thuộc tính đó , cũng không tự suy đoán tác giả là ai. Khi đọc 1 thuộc tính không tồn tại thì kết quả trả về sẽ là undefined

Nhưng trong thực tế , mình sẽ muốn hiện thị "Unknown" nếu chưa có thông tin tác giả. Để làm được như vậy thông thường mình sẽ làm như sau

const author = book.author === undefined ? "Unknown" : book.author;

Đoạn code ở trên sẽ hoạt động , nhưng quá dài dòng và nếu có nhiều thuộc tính cần phải gán giá trị mặc định thì rất tốn thời gian

JS cho phép viết ngắn hơn bằng Default Values trong Destructuring:

const { author  = "Unknown" } = book;
console.log(author);
--> Kết quả lúc này sẽ là Unknown.

1.6 Bản chất của dấu = trong Default Values:
Hãy quan sát đoạn code dưới đây:
const { author = "Unknown" } = book;
Đoạn code trên sẽ có 2 dấu bằng mang 2 vai trò khác nhau về mặt cú pháp :
 1. Dấu = sau author chỉ định giá trị mặc định cho biến giải nén.
 2. Dấu = cuối cùng sau book xác định object nguồn được dùng để giải nén.
Điểm quan trọng nhất:
 - Giá trị mặc định trong Destructuring chỉ được sử dụng khi giá trị lấy ra là undefined.
 - Nó không có nghĩa là cứ giá trị trống, giá trị 0 hay false thì JavaScript sẽ thay bằng giá trị mặc định.

1.7 Liên hệ với React 
Giả sử component nhận thông tin của người dùng 

    function UserCard({ name, status = "active" }) {
        return (
            <div>
            <h2>{name}</h2>
            <p>{status}</p>
            </div>
        );
    }
Nếu component được sử dụng như sau :
<UserCard name = "Trung" />
Thì Status sẽ nhận giá trị "active" vì props không cung cấp thuộc tính status, nên giá trị nhận được là undefined.

Nhưng nếu như mình truyền vào
<UserCard name = "Trung" status={false} />
Thì lúc này status sẽ nhận giá trị là false chứ không phải active

Đây là một lợi ích quang trọng của Default Values. Mình có thể tự gán giá trị cho các dữ liệu bị thiếu mà không vô tình ghi đè các giá trị hợp lệ như false và 0.

II Nesting Destructuring - phá hủy lồng nhau 
1. Tại sao chúng ta lại cần Nested Destructuring ?
Ở nội dung trước , mình đã biết cách lấy thuộc tính từ 1 object. Nhưng trong dự án thực tế, dữ liệu thường sẽ không đơn giản như vậy. Một object có thể chứa object khác hoặc chứa mảng các object
Ví dụ, 1 API trả về thông tin sinh viên:

const student = {
    name : "Trung",
    age : 20,
    address : {
        city : "TP.HCM",
        district : "District 12"
    }
};
Giả sử ở đây mình muốn lấy city thình mình có thể viết 
const city = student.address.city;

console.log(city); // "Ho Chi Minh City"

Cách này hoàn toàn đúng. Tuy nhiên, khi cần lấy nhiều thuộc tính lồng nhau, mình có thể dùng Nested Destructuring để lấy chúng trực tiếp từ cấu trúc dữ liệu.
2. Nested Object Destructuring:
Ta có đoạn code : 

const student = {
  name: "An",
  age: 20,
  address: {
    city: "Ho Chi Minh City",
    district: "District 1"
  }
};

const {
  address: { city }
} = student;

console.log(city); // "Ho Chi Minh City"

Lần đầu nhìn có thể thấy đoạn code khó đọc nhưng mình sẽ phần tích từng bước 
 Bước 1 : đọc cấu trúc object 
 student :
  - address :
    - city
    - district
 address là một thuộc tính của student , nhưng giá trị của address lại là một object khác
 Bước 2 : đọc cấu trúc destructuring:
  const {
    address : { city }
  } = student;
 
 Hãy đọc code theo thứ tự:
    1. Lấy thuộc tính address từ object student.
    2. Bên trong address, lấy thuộc tính city.
    3. Tạo biến city để nhận giá trị đó.
 Kết quả : console.log(city); // "Ho Chi Minh city"
 Điều quan trọng : cú pháp address : { city } không tạo biến address. Nó đi sâu vào object address để lấy city

3. Nested Destructuring kết hợp Renaming:
Chúng ta đã học cú pháp đổi tên:
const { name: fullName } = student;


Bây giờ kết hợp với object lồng nhau:
const student = {
  name: "Trung",
  address: {
    city: "Ho Chi Minh City"
  }
};

const {
  name: fullName,
  address: { city: cityName }
} = student;

console.log(fullName); // "Trung"
console.log(cityName); // "Ho Chi Minh City"


Có hai thao tác đổi tên ở đây:
 - name: fullName: lấy student.name, tạo biến fullName.
 - city: cityName: lấy student.address.city, tạo biến cityName.
Tên thuộc tính gốc không thay đổi. Object student cũng không bị sửa đổi.

4. Nested Destructuring với mảng bên trong object 
Dư liệu API có thể chứa mảng :
const course = {
    title : "How to learn JS in 14 day",
    instructor : {
        name : "Trung"
    },
    student : ["Ronaldo","Messi","Neymar"]
};

Giả sử ở đây mình muốn lấy tên giảng viên và sinh viên đầu tiên 
const {
    instructor : { name : instructorName },
    student : [firstStudent]
} = course;

console.log(instructorName); // Trung
console.log(firstStudent); // Ronaldo
Như vậy mình có thể nhận ra được là , có 2 kiểu cấu trúc xuất hiện ở đây: 
 1. Dấu ngoặc nhọn {...} dùng để destructuring object theo tên thuộc tính 
 2. Dấu ngoặc vuông [...] dùng để destructuring Array theo vị trí.
Khi chúng lồng vào nhau,mình chỉ cần nhìn cấu trúc dữ liệu để xác định cú pháp tương ứng.

5. Nested Destructuring kết hợp Default Values
Đây là phần ứng dụng trực tiếp kiến thức vừa học ở bài trước:

Cho đoạn code : 
const user = {
  profile: {
    name: "An"
  }
};

const {
  profile: {
    name,
    city = "Unknown"
  } = {}
} = user;

console.log(name); // "An"
console.log(city); // "Unknown"

ở đây, city không tồn tại trong profile, nên giá trị mặc định "Unknown" được sử dụng
Nhưng chúng ta phải cẩn thận: Default Value cho thuộc tính bên trong không tự bảo vệ khi object cha bị thiếu 
Ex : 
 const user = {};
 const {
    profile : {
        name = "Guest"
    } = {}
 } = user;

 console.log(name) // Guest

 Phần profile = {} bảo vệ trường hợp user.profile là undefined. Sau đó name = "Guest" xử lý trường hợp profile.name là undefined
 nếu bỏ = {} ở profile, JS sẽ báo lỗi khi cố destructuring thuộc tính bên tron profile đang là undefined.

 6. Function parameters Destructuring
 1. Vấn đề : khi một hàm nhận object: 
 Giả sử chúng ta đang xây dựng hàm hiển thị thông tin của 1 sinh viên 
 const student = {
  name : "Trung",
  age : 21,
  major : "IT",
 };

 function displayStudent(student){
  console.log(student.name);
  console.log(student.age);
  console.log(student.major);
 }

 displayStudent(student);
 
 Code sẽ chạy bình thường. Nhưng chúng ta phải viết student.name , student.age,.. mỗi khi muốn sử dụng dữ liệu
 Vấn đề sẽ xảy ra nếu như hàm nhận nhiều thuộc tính hơn thì lúc bây giờ code sẽ trở nên dài dòng
 --> Để giải quyết vấn đề này JS cho phép destructuring ngay tại tham số của hàm để lấy các thuộc tính cần thiết

 2.Cách viết Function Parameter Destructuring 
 Bây giờ ta sẽ viết lại đoạn code xây dựng hàm hiển thị thông tin của 1 sinh viên như trên nhưng lúc này sẽ sử dụng Parameter Destructuring

 const student = {
  name : "Trung",
  age : 21,
  major : "IT",
 };

 function displayStudent({name , age , major}){
  console.log(name);
  console.log(age);
  console.log(major);
 } 

 displayStudent(student);
 --> 2 output đều giống nhau nhưng với Parameter Destructuring thay vì nhận object vào một tham số tên student, hàm destructuring trực tiếp nhận object được truyền vào là các biến name , age , major sử dụng bên trong hàm.

 3. Tham số destructuring không phải object mới
 Đây là điểm chúng ta cần phải hiểu sâu
 Khi gọi displayStudent(student);
 Chúng ta đang truyền vào cho cả object student cho Hàm
 Hàm : 
 function displayStudent({ name, age }) {
    console.log(name);
    console.log(age);
 }
 Có thể hiểu tương đương về mặt ý tưởng như sau:
 function displayStudent(student) {
    const { name, age } = student;

    console.log(name);
    console.log(age);
}
Cách viết này giúp chúng ta thấy rõ hơn: Function Parameter Destructuring thực chất là áp dụng quy tắc destructuring ngay tại vị trí khai báo tham số 
!!! Lưu ý: Cú pháp này không có nghĩa là chúng ta truyền hai tham số riêng biệt. Thật chất chúng ta vẫn truyền một object duy nhất.
displayStudent(student); // Đúng
displayStudent(student.name, student.age); // Đây là cách truyền hai đối số riêng
--> 2 cách gọi ở trên có cấu trúc khác nhau
 4.Đổi tên biến trong tham số hàm 
 Ở phần trên chúng ta đã được học cú pháp:
 const { name : studentName } = student;
 khi đưa vào Function Parameter , quy tắc vẫn y nguyên:
 const student = {
  name : "Trung",
  age : 21
 };
 function displayStudent({ name : studentName , age }){
  console.log(studentName);
  console.log(age);
 }
 displayStudent(student);
 Trong hàm này :
  - name là tên thuộc tính cần Lấy
  - studentName là biến cục bộ được tạo 
  - age vừa là tên thuộc tính vừa là tên biến 
--> vì vậy nếu chúng ta viết console.log(name) trong hàm thì sẽ báo lỗi nếu không có biến name nào khác trong phạm vi truy cập. Biến được tạo từ thuộc tính name ở đây là studentName

 5. Kết hợp Default Value trong function Parameter:
 Ở phần này chúng ta sẽ kết hợp trực tiếp với bài Default Value đã học ở trên:
 function createUser({
  name = "Guest",
  role = "User",
 }){
  console.log(name);
  console.log(role);
 }
 
 createUser({
  name : "Trung"
 });

 --> Kết quả sẽ là:
 Trung 
 User 
 Giải thích :
 - name có giá trị là Trung, nên giữ nguyên
 - role không có trong object được truyền vào , nên nó là undefined vì vậy sẽ lấy giá trị mặc đinh "user".

 Chúng ta cũng có thể áp dụng Default Value để hỗ trợ trường hợp không truyền đối số nào vào hàm :
 function createUser({
  name = "Trung",
  role = "Guest"
 } = {}) {
  console.log(name);
  console.log(role);
 }
 createUser();

 --> Kết quả sẽ là :
 Trung 
 Guest

 ??? Tại sao lại cần dùng = {} ở ngoài cùng
 Vì nếu gọi createUser() mà không có đối số , tham số sẽ nhận undefined. JS không thể destructuring các thuộc tính của undefined
 cú pháp : 
 function createUser({ name = "Trung" } ={})
 có hai lớp Default Values khác nhau:
 1. ={} : giá trị mặc định cho toàn bộ tham số
 2. name = "Guest": giá trị mặc định cho thuộc tính name
 Đây là một ứng dụng rất hữu ích khi xây dựng hàm có nhiều tùy chọn

 6. Tại sao React sử dụng cú pháp này nhiều ?
 Trung React, component thường nhận dữ liệu từ props

 ví dụ : 
 function userIdCard(props){
  return <h2>{props.name}</h2>
 }
 
 ta có thể viết 
 function userIdCard({ name , age }){
  return (
    <div> 
      <h2>{name}</h2>
      <p>{age}</p>
    </div>
  );
 }
 
 Khi sử dụng :
 <UserCard name = "Trung" age = {20} />

 React truyền object props vào component, còn destructuring giúp chúng ta lấy trực tiếp name và age

 Vì vậy khi gặp cú pháp :
 function Component({ title , dedescription }){
  // ...
 }
 Hãy nhớ rằng đây chính là Function Parameter Destructuring không phải là một cú pháp riêng của React.

III. Spread Operator(...) và Rest Parameter(...)
1. Trước tiên : Tại sao JS lại có ... ?
Hãy tưởng tượng chúng ta đang có 1 chiếc hộp chứa 3 loại quả: Apple, Banana, Orange
 - Với Spread chúng ta sẽ mở hộp lấy từng loại quả ra Apple + Banana + Orange
 - Với Rest chúng ta sẽ gom các loại quả này thành 1 nhóm [Apple , Banana , Orange]
 --> Có thể hiểu đơn giản Spread là trãi ra còn Rest là thu gom 
 Đây là cách hình dung ban đầu:
  - Spread Operator : Trải các phần tử của một iterable hoặc các thuộc tính của một object ra
  - Rest Parameter/ Rest syntax : Gom nhiều giá trị hoặc thuộc tính còn lại vào 1 biến 
  Cả 2 đều dùng dấu ... Điểm khác biệt nằm ở vị trí xuất hiện và nhiệm vụ mà nó thực hiện chứ không phải ở ký hiệu.
2. Spread Operator - Trải các phần tử ra
 2.1 Spread với Array
 Giả sử chúng ta có 1 mảng:
 const fruits = ["Apple" ,"Banana","Orange"];
 console.log(fruits);
 ==> Kết quả : ["Apple", "Banana", "Orange"]
 Bây giờ nếu chúng ta viết 
 console.log(...fruits);
 Kết quả sẽ là Apple Banana Orange
 tại sao lại như vậy ?
 Khi viết ...fruits trong lời gọi hàm, JS trải các phần tử của mảng thành những đối số riêng biệt. Về mặt ý tưởng, câu lệnh trên tương đương với
 console.log("Apple", "Banana", "Orange");
 !!! Chú ý : Spread không phải là 1 vòng lặp và cũng không phải là một hàm. Nó là cú pháp của JS để trải các phần tử ra tại vị trí được phép sử dụng

 2.2 Spread để sao chép mảng
 Đây là một ứng dụng rất quan trọng trong lập trình thực tế:
 const original = [10,20,30];

 const copied = [...original];
 console.log(copied);
 ==> Output sẽ là [10, 20, 30]

 [...original] tạo ra một mảng mới có các phần tử giống nhau ban đầu
 original[10,20,30] -> Spread các phần tử sang mảng mới -> copied[10,20,30]
 --> 2 mảng này có nội dung giống nhau nhưng là 2 mảng khác nhau
 Để kiểm chứng
  const original = [10, 20, 30];
  const copied = [...original];

  console.log(original === copied); // false

  copied.push(40);

  console.log(original); // [10, 20, 30]
  console.log(copied);  // [10, 20, 30, 40]

  Tại sao original === copied lại trả về false ? Vì với Array, phép so sánh === kiểm tra xem hai biến có tham chiếu đến cùng một object không. Hai mảng được tạo riêng biệt nên chúng khác nhau

  !!! Lưu ý quan trọng: Spread tạo bản sang nông(shallow copy). Nếu mảng chứa các object hoặc mảng lồng nhau, những object lồng bên trong vẫn có thể được dùng chung giữa 2 mảng. Chúng ta sẽ quay lại phần này sau.

  2.3 Spread để gộp nhiều mảng
  Giả sử chúng ta đang có 2 danh sách sinh viên của 2 lớp:

  const classA = ["An", "Bình"];
  const classB = ["Chi", "Dũng"];

  const allStudents = [...classA, ...classB];

  console.log(allStudents);

  ==> Kết quả ["An", "Bình", "Chi", "Dũng"]
  Hãy so sánh 2 cách viết:
  // Cách 1: Sử dụng Spread
  const result1 = [...classA, ...classB];

  // Cách 2: Viết trực tiếp các phần tử
  const result2 = ["An", "Bình", "Chi", "Dũng"];
  Cả 2 cách đều tạo ra mảng có cùng nội dung. Tuy nhiên cách thứ nhất tiện hơn khi dữ liệu đến từ các biến và có thể thay đổi theo thời gian.
  Chúng ta cũng có thể thêm mới phần tử ở đầu hoặc cuối 
  const numbers = [2, 3, 4];

  const result = [1, ...numbers, 5];

  console.log(result);
  // [1, 2, 3, 4, 5]

  Ứng dụng thực tế : Gộp danh sách dữ liệu lấy từ API, tạo mảng mới khi cập nhật state trong React hoặc bổ sung phần tử mà không thay đổi mảng ban đầu

  2.4 Spread với Object
  Spread không chỉ dùng cho Array. Với Object, nó giúp sao chép và kết hợp các thuộc tính.

  const user = {
    name : "Trung",
    age : 21
  };

  const copiedUser = {...user};
  console.log(copiedUser);
  // { name: "Minh", age: 21 }

  console.log(user === copiedUser);
  // false

  muốn thêm thuộc tính mới thì sao ?

  const updateUser = {
    ...user,
    city : "Da Nang"
  };

  console.log(updateUser);
  // { name: "Minh", age: 21, city: "Da Nang" }

  Điểm hay là không cần viết hết lại các thuộc tính cũ 
  Nhưng nếu 2 object có cùng 1 thuộc tính thì sao ?

  const defaultConfig = {
    theme : "light",
    language : "vi"
  };

  const userConfig = {
    theme : "dark"
  };

  const config = {
  ...defaultConfig,
  ...userConfig
 };

  console.log(config);
  ==> kết quả sẽ là 
  {
    theme: "dark",
    language: "vi"
  }
  Tại sao theme là "dark" không phải là "light"?
  Vì khi trải object vào một object mới , nếu thuộc tính được cung cấp nhiều lần thì giá trị xuất hiện sau sẽ ghi đè giá trị trước
  Cũng vì quy tắc này nên thứ tự viết spread rất quan trọng :
  const config = {
    ...userConfig,
    ...defaultConfig
  };
  Ở đây theme sẽ là "light" vì defaultConfig xuất hiện sau.

  3.Rest parameters - gom các đối số loại
  Bây giờ chúng ta hãy chuyển sang phần thứ 2. Ở trên mình đã biết Spread dùng để trãi các phần tử ra. Vậy nếu 1 hàm cần nhận số lượng đối số không cố định thì sao?

  3.1 Vấn đề trước khi dùng Rest Parameter
  Giẳ sửa muốn viết 1 hàm tính tổng :

  function sum (a , b) {
    return a + b;
  }

  console.log(sum(10,20));
  console.log(sum(10,20,30));

  Ở lời gọi hàm thứ hai , chúng ta truyền vào 3 đối số nhưng chỉ khai báo a và b. Đối số thứ ba không được đưa vào phép tính
  Vậy nếu muốn hàm nhận được 2 3 5 hoặc 100 tham số thì sao?

  3.2 Giải pháp với Rest Parameters 
  function(...numbers){
    console.log(numbers);
  }
  sum(10,20,30);
  
  ==> kết quả [10, 20, 30]
  Đây là điểm khác biệt quan trong ...numbers trong danh sách tham số của hàm sẽ gom tất cả các đối số còn lại thành một mảng tên numbers
  Giờ thì mình có thể tính tổng:
  function sum(...numbers){
    let total = 0;

    for(const number of numbers){
      total += number;
    }
    
    return total;
  }
  console.log(sum(10, 20));          // 30
  console.log(sum(10, 20, 30));      // 60
  console.log(sum(1, 2, 3, 4, 5));   // 15
  console.log(sum());                // 0
  Hàm sum không cần biết trước số lượng đối số. Nó nhận chúng dưới dạng mảng rồi duyệt qua để tính tổng

  3.3 Kết hợp tham số thông thường với Rest 
  Đây là dạng thường sẽ gặp trong bài tập:

  function introduce(role, ...skills) {
  console.log(`Role: ${role}`);
  console.log(`Skills: ${skills}`);
  }

  introduce("Developer", "JavaScript", "C#", "SQL");
  ==> Kết quả :
  Role : Developer
  Skills : JavaScript,C#,SQL

  Phân tích lời gọi hàm :
  Đối số 1 : role nhận "Developer"
  Còn lại : ...skills gom "JavaScript", "C#" và "SQL" vào mảng skills.
 
  !!! Có một quy tắc rất quan trọng Rest parameter phải là tham số cuối cùng của hàm.
  // Hợp lệ
  function test(first, ...rest) {}

  // Không hợp lệ
  // function test(...rest, last) {}
  ==> Lý do: JavaScript cần xác định rõ từ vị trí nào trở đi các đối số được gom vào mảng rest.

  4. Rest trong Destructuring
  Sau khi vừa học Nested Destructuring và Object Destructuring ở phần trước. Rest cũng có thể kết hợp với những kiến trúc đó

  4.1 Rest với Array
  const numbers = [10, 20, 30, 40, 50];

  const [first, second, ...others] = numbers;

  console.log(first);  // 10
  console.log(second); // 20
  console.log(others); // [30, 40, 50]
  Cách đọc:
  - first nhận phần tử đầu tiên.
  - second nhận phần tử thứ hai.
  - ...others gom tất cả phần tử còn lại vào một mảng.
  Chú ý: others là một mảng, không phải một giá trị đơn.
  4.2 Rest với Object 
  const student = {
    id: 101,
    name: "Minh",
    age: 21,
    city: "Da Nang"
  };

  const { name, ...otherInfo } = student;

  console.log(name);
  // "Minh"

  console.log(otherInfo);
  // { id: 101, age: 21, city: "Da Nang" }

  Ở đây name được lấy riêng ra, còn ...otherInfo gom tất cả thuộc tính chưa được lấy ra thành một Object mới 

  Đây là cách hữu ích khi chúng ta muốn tách một thuộc tính nhưng vẫn giữ các thuộc tính còn lại.

  Ví dụ, chúng ta muốn bỏ password khỏi một Object trước khi gửi thông tin khác cho giao diện:

  const user = {
    username: "minh123",
    password: "secret",
    email: "minh@example.com"
  };

  const { password, ...publicUser } = user;

  console.log(publicUser);
  // {
  //   username: "minh123",
  //   email: "minh@example.com"
  // }
  !!! Lưu ý: Đây là ví dụ về thao tác dữ liệu phía JavaScript, không thay thế các biện pháp bảo mật ở server

  5. Phân biệt Spread và Rest - Phần cốt lõi  
    Spread Operator
    Trải ra
    const numbers = [1, 2, 3];

    const copy = [...numbers];


    Một mảng được trải các phần tử vào mảng mới.


    Rest Parameters
    Gom lại
    function collect(...numbers) {
      return numbers;
    }

    collect(1, 2, 3);


    Nhiều đối số được gom thành một mảng.


    Rest trong Destructuring
    Gom phần còn lại
    const [first, ...others] = [1, 2, 3];


    Lấy phần tử đầu tiên riêng ra, gom phần còn lại thành mảng.

    Tổng kết:
    Spread :
     + Ý nghĩa : trải dữ liệu ra
     + Trong lời gọi hàm : trải mảng thành các đối số
    Rest : 
     + Ý nghĩa : gom dữ liệu thành mảng
     + Trong khai báo hàm : Gom các đối số vào mảng 
     + Trong destructuring : Gom các phần tử hoặc thuộc tính còn lại.

    Ví dụ để nhớ lâu :
    const players = ["Ronaldo","Messi","Neymar"];

    // Spread trải mảng ra thành các đối số 
    Math.max(...players); // 3

    // Rest gom các đối số thành một mảng
    function getPlayers(...values){
      return values;
    }

    getPlayers("Trung","Vũ","Liêm"); // ["Trung","Vũ","Liêm"]

    Tips and tricks : ĐỪng cố gắng nhớ ... lúc nào cũng có một ý nghĩa cố định. Hãy nhìn vào vị trí nó xuất hiện để xác định nó đang thực hiện nhiệm vụ gì.

    6. Những lỗi newbie thường gặp
    Lỗi 1: Nhầm Spread với việc sao chép sâu
    const original = {
      profile: {
        name: "An"
      }
    };

    const copy = { ...original };

    copy.profile.name = "Bình";

    console.log(original.profile.name);
    // "Bình"


    Tại sao lại như vậy? Spread chỉ sao chép nông. Object profile bên trong vẫn được tham chiếu chung giữa hai object.
    Lỗi 2: Đặt Rest Parameter sai vị trí
    // Sai cú pháp:
    // function example(...values, last) {}


    Rest Parameter phải ở cuối danh sách tham số.
    Lỗi 3: Nghĩ rằng Rest trong destructuring lấy phần tử cuối
    const [first, ...rest] = [10, 20, 30, 40];

    console.log(rest);
    // [20, 30, 40]


    rest lấy các phần tử còn lại sau vị trí đã được destructure, không phải chỉ lấy phần tử cuối.
    Lỗi 4: Quên thứ tự ghi đè của Spread Object
    const a = { theme: "light" };
    const b = { theme: "dark" };

    console.log({ ...a, ...b }.theme); // "dark"
    console.log({ ...b, ...a }.theme); // "light"


    Thứ tự Spread có thể thay đổi kết quả.
